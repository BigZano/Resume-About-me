MIGRATION NOTES — Resume-About-me
Written 2026-08-09 for the move onto the SSH host.
Throwaway file. Read it, use it, delete it, commit the deletion.

===================================================================
THE SHORT VERSION
===================================================================

Python 3.12+ is the only requirement. There are no dependencies to
install. Clone, run the build, done.

    git clone https://github.com/BigZano/Resume-About-me.git
    cd Resume-About-me
    python3 src/main.py

If that prints "Site built successfully" you are fully migrated.

===================================================================
WHY THERE'S NOTHING TO INSTALL
===================================================================

Everything under src/ imports only the standard library — os, re,
shutil, pathlib, datetime, enum, math, sys, traceback, unittest.
No third-party packages are involved in a build.

Pillow shows up in the Windows .venv but nothing imports it. It was
used once, ad hoc, to recompress static/headshot.jpg from 4.4 MB down
to 57 KB. It is recorded in pyproject.toml under an "imgtools" group
so that job stays reproducible, but you do NOT need it to build.

(The group is not called "dev" on purpose — uv installs the dev group
automatically on every sync, which would have made the "nothing to
install" claim above false. Verified: plain `uv sync` installs zero
packages.)

===================================================================
OPTIONAL: ISOLATED INTERPRETER
===================================================================

Only if the host's system Python is older than 3.12, or you want the
env isolated. Project convention is uv with a project-local .venv —
never a global pip install.

    uv venv        # reads .python-version -> 3.12
    uv sync        # no runtime deps, just creates the env

Add the one-off image tool only if you actually need it:

    uv sync --group imgtools

===================================================================
WHAT THE CLONE DOES NOT GIVE YOU
===================================================================

These are gitignored on purpose and will be absent on the host. None
of them need to be copied over — they all regenerate:

    .venv/          recreate with `uv venv` (or skip entirely)
    log.txt         rewritten by every build
    __pycache__/    Python regenerates it
    *.pyc           same

Nothing else is missing. There are no secrets, no .env, no keys in
this repo — working tree or history — so there is nothing to hand-
carry outside of git.

===================================================================
COMMANDS ON THE HOST
===================================================================

    ./build.sh              build (or: python3 src/main.py)
    ./scripts/main.sh       build + serve docs/ on :8888

Do not trust ./test.sh. It runs `unittest discover -s src`, which finds
ZERO tests and exits quietly — src/tests/ is not an importable package,
so discovery never descends into it. It has been reporting nothing for
a long time (src/tests/ last changed in b3a67d1).

The 9 test files under src/tests/ are also stale on their own terms:
force them to run and roughly half fail or error, partly because they
disagree about whether to import `textnode` or `src.textnode`. This is
pre-existing and has nothing to do with the migration — just don't read
a silent ./test.sh as "tests passed". Worth a cleanup pass sometime.

Build correctness is currently verified by running the build and
checking the output, not by the suite.

The .sh scripts are bash and were being run from Windows before, so
if they refuse to execute:

    chmod +x build.sh test.sh scripts/main.sh

Line endings are the other likely papercut. The repo has CRLF in
places from the Windows side. If bash complains about '\r':

    sed -i 's/\r$//' build.sh test.sh scripts/main.sh

===================================================================
THE ONE RULE THAT MATTERS
===================================================================

docs/ is GENERATED OUTPUT. Never hand-edit anything in it.

Source lives in:
    content/            markdown — resume.md, aboutme.md, dev_diary/
    static/             css, fonts, fire.js, images
    template.html       shell for content pages
    titlepage.html      shell for the landing page
    dev_diary_template.html   shell for blog posts

The build wipes docs/ and rebuilds it from those. Anything typed
directly into docs/ disappears on the next build, silently.

New blog post = drop YYYY-MM-DD-slug.md into content/dev_diary/ and
rebuild. Index and pagination generate themselves.

===================================================================
DEPLOYMENT (unchanged by the move)
===================================================================

GitHub Pages serves branch main, folder /docs. CNAME pins the domain
to bretzanotelli.work and the build copies it into docs/ for you.

    ./build.sh
    git add -A && git commit -m "rebuild site"
    git push origin main

Pages rebuilds on push. Repo is public, which is what keeps Pages
working on the free plan — if it ever goes private the site goes
down unless the account is on Pro.
